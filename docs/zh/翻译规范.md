# 翻译规范

本文档定义中文化的翻译标准与流程，确保与上游同步时可重复、可审计。

## 文案原则
- 保持信息完整，不省略技术要点。
- 保留代码片段、命令、参数、路径、环境变量名称原样。
- 语气简洁、直接，避免口语化或营销语气。
- 中英文混排时使用中文标点；英文单词与数字之间留空格。

## Key 命名规范
- 使用分层命名：`模块.上下文.语义`
- 示例：`codex_cli.error.unsupported_platform`
- 避免使用短而模糊的 key（如 `error1`）。

## 占位符规范
- 占位符使用 `{name}` 形式。
- 保持占位符数量与含义一致。
- 不改变占位符语义顺序。

## 同步流程
1. 上游更新后，先完成 `l10n/zh` 对齐。
2. 使用差异对比找到新增/修改的英文文案。
3. 更新 `locales/zh-CN.json` 中的对应 key。
4. 更新 `meta.last_sync`。
5. 若涉及文档，补充 `docs/zh/` 中的中文版本。

## 质量检查清单
- 是否保留了命令、参数、路径？
- 占位符是否一致？
- 语义是否与英文原文一致？
- 是否影响 CLI 输出可读性？
